🔐 1. โฟลว์การแลกเปลี่ยน Token (Token Exchange & Lifecycle Flow)
1

ล็อกอินผ่านเซิร์ฟเวอร์กลาง

ผู้ใช้กรอก Username / Password ผ่านหน้าเว็บ กลุ่ม 4 ส่งคำขอ POST ไปยังเซิร์ฟเวอร์กลางของกลุ่ม 3 เพื่อตรวจสอบความถูกต้อง

POST /api/v1/auth/login Target: 192.168.100.103:8000 Body: { username, password }
2

ออก Group 4 JWT Token

เมื่อกลุ่ม 3 ยืนยันรหัสถูกต้อง Backend กลุ่ม 4 ออก Token เฉพาะระบบตนเอง เข้ารหัสลายเซ็น HS256 มีอายุใช้งาน 120 นาที

{ "sub": "67200324", "role": "student", "exp": 1784627200 }
3

จัดเก็บใน Client Storage

เบราว์เซอร์รับ Token แล้วจัดเก็บใน localStorage อย่างปลอดภัย และดักจับแนบไปกับ Header ทุก Request ผ่าน Axios Interceptor

Authorization: Bearer <token> Client: localStorage.setItem( 'access_token', token )
4

ตรวจสอบสิทธิ์ & ป้องกัน IDOR

Backend ถอดรหัส Token และดึง Role/ID โดยตรง หากเป็นนักศึกษา จะบังคับสืบค้นเฉพาะ student_id = token.sub เท่านั้น ป้องกัน IDOR เด็ดขาด

verify_token() -> Claims if role == "student": student_id = claims["sub"]
5

บันทึก Audit Log ลง DB

ระบบบันทึกประวัติการเข้าใช้งานลงตาราง user ใน MariaDB แบบ Asynchronous Background Task ไม่หน่วงเวลาการตอบกลับข้อมูล

INSERT INTO user (student_id, role, last_login) VALUES (:sub, :role, NOW())
📡 2. โฟลว์การซิงก์ข้อมูล IoT (IoT Ingestion & Real-Time Pipeline)
A

อุปกรณ์ทาบบัตร RFID

นักศึกษาหรืออาจารย์ทาบบัตร RFID หน้าห้องเรียน เครื่องอ่านบันทึก UID, วันที่, เวลา และรหัสห้องเรียนทันที

Classroom Readers: UID: 04A1B2C3D4 Room: EN4101 Time: 2026-10-20 08:30:15
B

IoT Server (กลุ่ม 6)

ฮาร์ดแวร์ส่งสัญญาณผ่าน MQTT / HTTP เข้าสู่เซิร์ฟเวอร์ IoT ของกลุ่ม 6 เพื่อรวมรวมและเปิดบริการ API สำหรับดึงข้อมูล

GET /api/logs/all Host: 192.168.100.106:3000 Content-Type: application/json
C

Ingestion Worker (กลุ่ม 4)

แบ็กกราวด์เซอร์วิสของกลุ่ม 4 โพลลิ่งข้อมูลทุก 5 วินาที พร้อมระบบ Retry อัตโนมัติ (Exponential Backoff) ป้องกันการเชื่อมต่อล้มเหลว

Async Loop (interval: 5s) httpx.AsyncClient(timeout=5) Max Retries: 3 with backoff
D

Cleansing & ตัดข้อมูลซ้ำ

ปรับรูปแบบวันที่เป็น Bangkok Time (GMT+7) และสร้าง Hash ลายนิ้วมือข้อมูลด้วย MD5 เพื่อตัดแถวซ้ำ (Deduplication) ก่อนบันทึก

hash = MD5(UID + Room + Time) if hash in seen_hashes: skip_duplicate()
E

MariaDB & Live Dashboard

บันทึกลงตาราง web_app ในฐานข้อมูล web_app_db พร้อมแจ้ง WebSocket / Auto-refresh ให้แดชบอร์ดอัปเดตแบบเรียลไทม์

INSERT INTO web_app (...) VALUES (...) -> Auto-refresh Dashboard

💡 จุดเด่นด้านความมั่นคงปลอดภัย (Security Highlights สำหรับพรีเซนต์)

1. สถาปัตยกรรมแยกส่วนการยืนยันตัวตน (Decoupled Auth)

กลุ่ม 4 ไม่ได้เก็บรหัสผ่านของผู้ใช้งานไว้เอง แต่ใช้ Central Auth จากกลุ่ม 3 ลดความเสี่ยงกรณีฐานข้อมูลรั่วไหล และสร้าง Token ภายในที่จำกัดสิทธิ์เฉพาะฟังก์ชันที่จำเป็น

2. การป้องกัน IDOR อย่างสมบูรณ์แบบ (Anti-IDOR by Design)

บทบาทนักศึกษาถูกจำกัดให้สืบค้นข้อมูลของตนเองเสมอ โดยระบบดึง student_id จาก Claims ภายใน JWT Token โดยตรง ไม่เปิดช่องให้ส่ง query string มาแอบดูข้อมูลของเพื่อน

3. ท่อข้อมูล IoT ที่ทนทานต่อความผิดพลาด (Resilient IoT Pipeline)

มีระบบกรองข้อมูลซ้ำ (Deduplication) ด้วย MD5 fingerprint, ปรับปรุง timezone สู่ Bangkok GMT+7, และกลไก fallback ไม่ให้แดชบอร์ดล่มแม้เครือข่ายกลุ่ม 6 จะมีปัญหาชั่วคราว

4. การตรวจสอบย้อนหลัง (Audit Trail Logging)

ทุกการเรียกใช้งาน API ที่สำเร็จและไม่สำเร็จ มีการบันทึกประวัติการเรียกใช้ สิทธิ์ของผู้ใช้ และเวลาลงฐานข้อมูลอย่างเป็นระบบเพื่อการสอบสวนและติดตามย้อนหลัง
