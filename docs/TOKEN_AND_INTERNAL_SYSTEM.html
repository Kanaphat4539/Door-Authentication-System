1. ภาพรวมการทำงานด้วย JWT Token

ระบบกลุ่ม 4 นำมาตรฐาน JSON Web Token (JWT) มาใช้ในการระบุตัวตนและตรวจสอบสิทธิ์ของผู้ใช้งานในรูปแบบ Stateless Authentication เพื่อความปลอดภัยสูงและการตอบสนองที่รวดเร็ว

🔐 1. Centralized Auth

ยืนยัน Username/Password จากระบบกลางของ กลุ่ม 3 (192.168.100.103:8000) เท่านั้น

✍️ 2. Signed by Group 4

ออก Token เฉพาะของกลุ่ม 4 พร้อม Digital Signature ด้วย HS256 และความลับ JWT_SECRET

🛡️ 3. RBAC & IDOR Guard

แยกสิทธิ์ระหว่าง อาจารย์ (Teacher) และ นักศึกษา (Student) ป้องกันการแอบดูข้อมูลผู้อื่น

⏱️ 4. Expiration Policy

กำหนดอายุ Token ไว้อย่างเข้มงวด 120 นาที เมื่อหมดอายุต้องเข้าสู่ระบบใหม่

2. โครงสร้างของ Token (JWT Claims)

Token มีองค์ประกอบ 3 ส่วนคั่นด้วยจุด (.) คือ Header.Payload.Signature

// ส่วนของ Payload (Claims)
{
  "sub": "67200324",            // รหัสผู้ใช้งาน (รหัสนักศึกษา หรือ Username ของอาจารย์)
  "role": "student",            // ระดับสิทธิ์: "teacher" หรือ "student"
  "iat": 1784620000,            // เวลาที่ออก Token (Unix Timestamp)
  "exp": 1784627200             // เวลาหมดอายุของ Token (120 นาที)
}

💡 จุดเด่นด้านความปลอดภัยของกลุ่ม 4

1. Anti-IDOR: รหัสนักศึกษาถูกฝังอยู่ใน Token (sub) ทำให้นักศึกษาไม่สามารถแก้ไข URL เพื่อดูประวัติของเพื่อนได้
2. Non-blocking Audit Logging: บันทึกประวัติลงตาราง user แบบ Asynchronous เบื้องหลัง หน้าเว็บจึงทำงานรวดเร็วไม่สะดุด
3. Strict Signature Verification: หาก Token ถูกดัดแปลงแม้แต่ตัวอักษรเดียว ระบบจะส่ง 401 Unauthorized ทันที
