# แผนการพัฒนา Auth API

> **สำหรับเอเจนต์ที่ทำงานตามแผน:** ดำเนินงานในเซสชันนี้โดยใช้เครื่องมือที่มีอยู่ในระบบ ยังไม่ได้ติดตั้ง skill ย่อยของ superpowers สำหรับดำเนินงานตามแผนที่อ้างถึง

**เป้าหมาย:** สร้าง API ยืนยันตัวตนที่รันได้ โดยเว้นค่าการเชื่อมต่อ RADIUS server ไว้ก่อน

**สถาปัตยกรรม:** แยกส่วนการอ่านค่าตั้งค่าจาก environment, รูปแบบข้อมูล JSON,
การยืนยันตัวตนผ่าน RADIUS, การสร้างและตรวจสอบ JWT และ routes ออกจากกัน
มีโหมดจำลอง (mock) สำหรับพัฒนาที่ต้องเปิดใช้เอง เพื่อทดสอบก่อนบริการภายนอกพร้อมใช้งาน

**เทคโนโลยีที่ใช้:** Python 3.14, FastAPI, Pydantic Settings, PyJWT, pyrad, pytest, httpx2

**ข้อกำหนดการออกแบบ:** `docs/superpowers/specs/2026-10-07-auth-api-design.md`

## ข้อกำหนดที่ใช้กับทุกส่วน

- ห้าม commit ค่าความลับจริง หรือกู้คืนไฟล์เดิมที่ถูกลบไว้แล้ว
- Login รับข้อมูล JSON และ `/auth/me` ใช้ Bearer token โดยยังไม่กำหนด role หรือสิทธิ์เปิดประตูขึ้นเอง
- หากยังไม่ได้ตั้งค่า RADIUS ให้ตอบ `503`; ต้องเปิดโหมด mock เอง และห้ามสลับไปใช้โดยอัตโนมัติเมื่อ RADIUS มีปัญหา
- รองรับ RADIUS แบบ PAP เท่านั้น ต้องยืนยันความเข้ากันได้กับทีมที่ดูแล RADIUS

`auth-api/app/main.py`, `auth-api/app/routes/auth.py`,

`auth-api/app/schemas/auth.py` และไฟล์ `__init__.py` ของแต่ละ package

**รูปแบบฟังก์ชันที่ใช้เชื่อมต่อระหว่างส่วน:** `create_app(settings: Settings | None = None) -> FastAPI`;
`authenticate(username: str, password: str, settings: Settings) -> bool`;
`create_access_token(username: str, settings: Settings) -> str`;
`decode_access_token(token: str, settings: Settings) -> str`.

- [x] เขียนการทดสอบพฤติกรรมด้วย `TestClient(create_app(Settings(_env_file=None, ...)))`

- [x] พัฒนาค่าตั้งค่า, RADIUS, token, schemas และ routes ให้เป็นไปตามข้อตกลงที่ระบุในเอกสาร
- [x] รันการทดสอบทั้งหมดและแก้ไขส่วนที่ทำงานไม่ตรงข้อกำหนด โดยไม่เปลี่ยนผลที่คาดหวังซึ่งถูกต้องอยู่แล้ว

## ผลการตรวจสอบ

- ก่อนพัฒนา การทดสอบไม่ผ่านเพราะยังไม่มีแอปพลิเคชัน หลังพัฒนาชุดแรก การทดสอบผ่านทั้ง 29 กรณี
- ผู้ตรวจโค้ดแบบอ่านอย่างเดียวไม่พบปัญหาระดับวิกฤตหรือสำคัญ พบกรณี NAS-Identifier ยาวเกินกำหนด
  จึงจำลองปัญหา เพิ่มการทดสอบ 4 กรณีที่ไม่ผ่าน แล้วแก้ด้วยการตรวจสอบค่าตั้งค่า
- ชุดทดสอบปัจจุบันผ่านทั้ง 33 กรณี แม้กำหนดให้ warning ถือเป็น error และคำสั่ง `pip check` ผ่าน
- การทดสอบเชื่อมต่อ RADIUS server จริงผ่าน UDP ยังรอค่าตั้งค่าจากทีมที่ดูแล RADIUS
