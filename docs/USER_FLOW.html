เส้นทางการใช้งานของอาจารย์ (Teacher Flow)

เน้นการกำกับดูแลภาพรวม การตรวจสอบห้องเรียน และวิเคราะห์สถิติ

1

เข้าสู่ระบบด้วยบัญชีผู้สอน

กรอก Username และ Password ระบบตรวจยืนยันสิทธิ์กับกลุ่ม 3 และระบุบทบาทเป็น teacher

Centralized Auth
2

อ่านการ์ดสถิติภาพรวมทั้งระบบ (System Stat Cards)

เห็นจำนวนห้องที่เปิดใช้งานทั้งหมด, ยอดการเข้าเรียนรวมของทั้งคณะ และสถิติผู้เข้าใช้ห้องรายวัน โดยการ์ดจะคงค่าสถิติรวมของระบบไว้เสมอแม้ทำการค้นหา

Global Analytics
3

ค้นหาและฟิลเตอร์เจาะจง (Multi-dimensional Search)

มีช่องค้นหาตามรหัสนักศึกษา (Search Keyword), เลือกห้องเรียน (Room Dropdown), เลือกวันที่ และเลือกดูเฉพาะคนที่กำลังใช้งานห้องเรียน (ACTIVE)

Search & Audit
4

ตรวจสอบและเช็กชื่อผ่าน Access Log Table

ตารางแสดงประวัติของทุกคน ทุกห้องเรียน มีระบบ Pagination เปลี่ยนหน้า พร้อมระบบบันทึก Audit Log พฤติกรรมการสืบค้นอัตโนมัติ

Audit Trail
5

ซิงก์ดึงข้อมูล IoT แบบ Manual (Live Sync)

กดปุ่ม "ซิงก์ข้อมูล IoT" เพื่อดึงบันทึกการแตะบัตรสดใหม่จากเซิร์ฟเวอร์กลุ่ม 6 มารวมในฐานข้อมูลทันทีโดยไม่ต้องรอรอบโพลลิ่ง

Manual IoT Ingestion

เส้นทางการใช้งานของนักศึกษา (Student Flow)

เน้นการตรวจสอบประวัติการเข้าเรียนและสถิติการแตะบัตรส่วนบุคคล

1

เข้าสู่ระบบด้วยรหัสนักศึกษา

กรอกรหัสนักศึกษาและรหัสผ่าน ระบบออก Token ที่ระบุ role: student และ sub: 67200324

Zero-Trust JWT
2

อ่านการ์ดสถิติส่วนบุคคล (Personal Stat Cards)

การ์ดแสดงเฉพาะยอดการเข้าเรียนของตนเอง เช่น เข้าเรียนแล้วกี่ครั้ง เข้าใช้ไปกี่ห้องเรียน ไม่แสดงสถิติรวมของเพื่อนหรือภาพรวมระบบ

Personal Privacy
3

ป้องกัน IDOR โดยอัตโนมัติ (Anti-IDOR Protection)

ระบบล็อกช่องค้นหารหัสและซ่อนช่องป้อนรหัสนักศึกษาคนอื่น นักศึกษาทำได้เพียงกรองห้องเรียนหรือวันที่ของตนเองเท่านั้น

IDOR Guard
4

ตรวจสอบประวัติการแตะบัตรตนเอง (Personal Logs)

ตรวจสอบความถูกต้องว่าเครื่องทาบบัตร RFID หน้าห้องเรียนบันทึกเวลาเข้าเรียน (IN) หรือแตะออก (OUT) ถูกต้องครบถ้วนหรือไม่

Attendance Check
5

สลับภาษาและออกจากระบบอย่างปลอดภัย

สามารถสลับภาษาเมนูเป็นอังกฤษ/ไทยได้ และเมื่อออกจากระบบ ระบบจะทำลาย Token ในเครื่องทันที

Secure Logout

🛡️ จุดเด่นด้าน UX และ Security ใน User Flow ของกลุ่ม 4

1. การแบ่งบทบาทแบบเบ็ดเสร็จ (Role-Based Divergence)

ผู้ใช้ล็อกอินผ่านประตูเดียว แต่หน้าจอและการอนุญาตเข้าถึงฟังก์ชันจะปรับเปลี่ยนตาม Claims ใน Token อัตโนมัติ ป้องกันความสับสนในการใช้งาน

2. ความสม่ำเสมอของสถิติ (Consistent Stat Cards)

การ์ดสรุปสถิติด้านบนจะคงค่าสถิติหลักของบทบาทนั้นเสมอ (อาจารย์เห็นสถิติรวมทั้งระบบ / นักศึกษาเห็นสถิติรวมของตนเอง) ไม่ลดจำนวนลงตามการกดฟิลเตอร์ตาราง

3. ความมั่นคงปลอดภัยระดับ Zero-Trust & Anti-IDOR

แม้ผู้ใช้ฝั่งนักศึกษาจะพยายามดัดแปลง JavaScript ในเบราว์เซอร์หรือยิง API หลังบ้าน ระบบ Backend จะบังคับ override ด้วยรหัสนักศึกษาจาก Token เสมอ

4. การตรวจสอบคนอยู่ในห้อง (Active Room Occupancy)

อาจารย์และนักศึกษาสามารถเลือกดูสถานะ "กำลังใช้งาน" เพื่อทราบว่าขณะนี้มีใครยังอยู่ในห้องเรียนแบบเรียลไทม์จากการประมวลผลคู่ IN/OUT ของ IoT
