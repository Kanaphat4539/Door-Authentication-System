สำหรับระบบเปิด-ปิดประตูห้องปฏิบัติการ

FastAPI · RADIUS · JWT

ปัญหาและวัตถุประสงค์

  • ระบบประตูห้องปฏิบัติการต้องรู้ว่า "ใครเป็นใคร" ก่อนอนุญาตให้ใช้งาน

  • สร้าง API กลางที่รับ username/password แล้วตรวจกับ RADIUS
  • รับบทบาทจากผลตอบกลับของ RADIUS แล้วออก JWT อายุสั้นที่มีบทบาทให้ Web-App (กลุ่ม 4) และฮาร์ดแวร์ IoT (กลุ่ม 5) นำไปใช้ต่อ

ขั้นตอน Auth Flow

Client ส่ง POST /auth/login พร้อม username และ password
ตรวจรูปแบบข้อมูลและตรวจว่าตั้งค่าคีย์ JWT แล้ว (ไม่เช่นนั้น 503)
สร้าง Access-Request (PAP) + NAS-Identifier + Message-Authenticator ส่งไป RADIUS
ตรวจ response และ Message-Authenticator ของ RADIUS ก่อนเชื่อผล
Access-Reject → 401 / Access-Accept → อ่านบทบาท (role) จากผลตอบกลับของ RADIUS
ออก JWT ที่มี role (หาก RADIUS ไม่ส่ง role จะเดาจากชื่อผู้ใช้ ค่าเริ่มต้น student)
Client แนบ Authorization: Bearer ไปที่ GET /auth/me เพื่อตรวจ token และรับ role

API Endpoints

Method / Pathหน้าที่Response
GET /healthตรวจสถานะบริการ200 {"status":"ok"}
POST /auth/loginยืนยันตัวตนผ่าน RADIUS รับ role จากผลตอบกลับ แล้วออก JWT200 / 401 / 422 / 503
GET /auth/meตรวจ Bearer token คืน username และ role200 / 401 / 503

โครงสร้างข้อมูล

Request / Response ของ APILoginRequest: username (1–253 bytes), password (1–128 bytes ไม่มี NUL)
TokenResponse: access_token, token_type="bearer", expires_in
UserResponse: username, role
JWT Claimssub, iat, exp, iss (auth-api), aud (door-system)
role (บทบาท: student / teacher / admin / staff)
อายุเริ่มต้น 15 นาที (1–60)

ความปลอดภัย

  • คีย์ JWT ยาวอย่างน้อย 32 bytes แยกจาก RADIUS shared secret และไม่เก็บในซอร์สโค้ด
  • ตรวจ JWT ครบ: อัลกอริทึม HS256, iss, aud และ claims บังคับ sub/iat/exp/iss/aud
  • ตรวจ Message-Authenticator และ reply ของ RADIUS; UDP แบบ connected รับตอบจาก peer เดียว
  • รหัสผ่านไม่ถูกบันทึกหรือส่งกลับ และ error 422 ไม่ส่งค่าที่ผู้ใช้กรอกกลับ
  • Cache-Control: no-store บน login / me
  • ไม่รองรับ RADIUS challenge/MFA จะตอบ 503 อย่างชัดเจน
